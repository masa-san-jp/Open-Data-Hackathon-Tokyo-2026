# OPEN-ISSUES — living-zone-navi

## D3（医療機関）をward単位で解決できず、都全域の「災害拠点病院等」に狭めた（2026-08-23, T01）

- design-spec §3 の D3 は「医療機関」全般を想定しているが、江東区が公開しているのは
  梅毒抗体検査・肝炎ウイルス検査・予防接種など**手続き特化のXX実施医療機関一覧**のみで、
  一般的な医療機関一覧（住所・座標つき）は区単位に存在しない（カタログ実測 2026-08-23）。
- 都全域の代替候補も「救急医療機関一覧」「医療機関等台帳」はHTML（JS描画ページ）で、
  urllibで取得しても生データではなくページ本体しか返らない。
- 機械可読なCSVとして唯一実在するのが東京都保健医療局「東京都の災害拠点病院等」
  （`https://www.hokeniryo.metro.tokyo.lg.jp/documents/d/hokeniryo/kyotenbyoinlist`）。
  座標列は無く住所のみ。江東区内は4施設（東京都立墨東病院は所在地表記が墨田区のため対象外）。
- 判断: D3はこの災害拠点病院リストに**スコープを狭めて**取得する。座標が無いため
  T03（reach判定）では「位置不明」に計上される想定。オーナー判断で仕様変更（区の別データ探索
  や住所からの手動プロット等）が必要であれば、この行を更新すること。

## 実装計画の「Phase 0 完了条件＝cool・barrier_freeの2ギャップ」と実データが食い違う（2026-08-23, T02）

- 実装計画 §3 は Phase 0 完了時の欠損パネルを「最低2行（cool・barrier_free）」と想定しているが、
  江東区は実際にはクーリングシェルター（D2）を公開しており「cool」ギャップは発生しない。
- 代わりに、T01で発生した「medical（D3スコープ狭小化）」ギャップが barrier_free と並ぶ
  2件目になっている。`verify.py`の固定点（gapsが空ならfail）は満たしているが、
  実装計画の文言どおりの内訳（cool・barrier_free）ではない。オーナー判断で文言修正が必要なら
  実装計画側を直すこと（データ側を偽装して「cool」ギャップを無理に作らない）。

## design-spec §8「reach値は5値のみ」と§4の定義（4値）が食い違う（2026-08-23, T02）

- §4は reach を near／far／out／unknown の4値と定義しているが、§8本文は「5値」と書いている。
- `scripts/verify.py` は§4の4値を正としてvalidateしている。5値目が何を指すか不明なため、
  想像で値を追加していない。オーナー判断で5値目の意図が分かれば追記すること。
