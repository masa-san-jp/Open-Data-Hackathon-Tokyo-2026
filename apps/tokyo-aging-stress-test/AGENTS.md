# エージェント向け 作業規約

**着手する前にこの1枚を読む。** 次に `SPEC.md`、それから `tasks/` の担当分。

## 1. 進め方

1. `tasks/` から**まだ誰も着手していない最小番号**を取る
2. そのファイルの先頭を `status: doing` に書き換えて**先にコミット**（他のエージェントと衝突しないため）
3. 実装する
4. `python3 scripts/verify.py` が通るまで終わらない
5. `status: done` にして、**何をしたかを1〜3行**そのファイルの末尾に追記してコミット

**このリポジトリは複数のエージェントと人が同時に触る。**
- 触るのは自分のタスクが名指ししたファイルだけ
- `git pull --rebase` してから push する
- 作業ブランチを共有チェックアウトに出したままにしない

## 2. 守ること

- **数字を作らない。** 出せない値は「出せない」と画面に書く。推定で埋めない
- **欠けを消さない。** 結合できない9自治体は `excluded` に残し、画面にも出す
- **2045年より先へ外挿しない。** 就業者・世帯の推計がそこで切れる
- **`verify.py` の固定点を、通すために書き換えない。** 落ちたら公開元で何が変わったかを先に調べ、
  分かったことを `OPEN-ISSUES.md` に書いてから直す
- **外部CDN・外部APIを画面から呼ばない。** プロトタイプは file:// で開けること
- **個人名を入れない。** このリポジトリは公開されている

## 3. 「できた」と言ってよい条件

```
python3 scripts/fetch_sources.py && \
python3 scripts/build_dataset.py && \
python3 scripts/verify.py
```

が **3本とも非ゼロ終了なし**。加えて Phase 1 は
`prototype/index.html` を**実際にブラウザで開いて、53行の一覧と見出しの数字が出ること**を目で見る。
「実装した」は完了ではない。**開いて見えた**が完了。

## 4. 詰まったとき

- 取得が 403 で止まったら、**認証が要ると決めつけない**。順番は
  ①機械向けの口（API・カタログ）を探す ②User-Agent をブラウザ相当にする ③それでも駄目ならブラウザ。
  `fetch_sources.py` は既に②を入れてある
- HTTP 200 でも中身がポインタや CAPTCHA のことがある。**サイズと先頭行を必ず見る**
  （`fetch_sources.py` の検査がこれをやっている）
- 仕様が足りないと思ったら、想像で埋めずに `OPEN-ISSUES.md` に1行足して、
  現時点で出せる形を出す
