# まちかどQR v0.1 レビュー結果と改善内容

- レビュー日: 2026-08-23
- 対象: `docs/design/` と `apps/machikado-qr/`
- 対象版: 設計仕様書 `e68d7db`、プロトタイプ `95562f9` を起点に確認
- 結論: コンセプトは明快だが、v0.1は「候補地デモ」「安全な現在地表示」「未検証の帰路案内」が同じ画面と説明に混在していた。公開には使えないが、デモとしては短時間で改善可能だったため、Phase 0用v0.2へ修正した。

## 1. 総評

強い点は三つある。

1. 「位置を推定する」のではなく「位置が確定した点を街に置く」という課題設定が明確
2. 住所を最上位にし、110・119を直接発信に限定する安全思想が一貫
3. 元データの異常を実測し、不明値を推定補完しない姿勢がある

一方、v0.1は設計思想に実装が追いついていなかった。特に、場所番号重複、交通データの座標異常、帰り道の仕様不一致、候補店舗を現在地点として扱う点は、誤った場所又は移動を示し得るため優先度P0と判断した。

## 3. 仕様と実装の差分

### 3.1 帰り道

v0.1の説明は「帰る方向にある40〜400mの次のステッカーを名指しする」だったが、コードは次を行っていた。

- 帰る場所は住所文字列だけ保存
- 住所を緯度経度へ変換しない
- 方向計算関数は呼ばれない
- 給水スポットと駅を現在地から近い順に表示

したがって、画面は「帰り道」ではなく「現在地周辺情報」だった。v0.2では周辺情報を独立ボタンに分け、帰り道には帰る場所番号を必須とした。ただし直線距離しか見ないため、通常モードでは停止している。

### 3.2 データ状態

「帰宅支援ステーション協力店舗」は災害時協力の一覧であり、まちかどQRの設置同意や設置事実を表さない。v0.1のUIはこの違いを利用者へ示さなかった。v0.2では次を分離した。

| 状態 | 意味 | Phase 0での扱い |
|---|---|---|
| `candidate` | 交渉候補 | デモ警告付きで表示 |
| `installed` | 同意・現地確認・設置済み | 未実装 |
| `suspended` | 異常・剥離・一時停止 | 未実装 |
| `retired` | 恒久廃止 | 未実装 |

### 3.3 データ品質

v0.1の東京都矩形と自治体近接判定は、明白な範囲外座標を落とす点で有効だった。しかし、同じ自治体内に見える誤座標や大量の同一座標を検知できなかった。

交通データの実測:

- 全268行
- 異なる座標147組
- 最大クラスター: 同一座標110行
- JR信濃町、千駄ヶ谷、大久保、中野、駒込など異なる駅が同一座標を共有

この状態で「駅67点」と表示するより、駅機能を外す方がプロダクトの安全原則に合う。よってv0.2では全駅を隔離した。

## 4. v0.2で実装した改善

| 領域 | 改善 |
|---|---|
| デモ | 依存不要の `demo.html`、固定シナリオ、全電話不発信 |
| UI | 住所優先、常設音声ボタン、候補地警告、周辺地点と帰り道の分離 |
| 安全 | 公開経路フラグOFF、遠距離・次点なしで移動停止、交通データ隔離 |
| プライバシー | 送信なし、名前空間付きlocalStorage、削除操作 |
| セキュリティ | `innerHTML` 排除、JSONエスケープ、外部リソースなし、CSP |
| データ | 自治体最長一致、コード重複ビルド停止、入力ハッシュ、品質レポート |
| 保守 | `src/`と生成物を分離、設定と出典をJSON化 |
| 品質保証 | `make verify`、Python/JavaScript構文検査、11件の自動テスト |
| 自律実装 | `AGENTS.md`、`CLAUDE.md`、依存付き `TASKS.md`、停止条件 |

## 5. 残存リスク

### 公開を禁止する残存リスク

- 設置同意と設置済み台帳がない
- 既存の連番場所コードは元データの並べ替えで変わり得る
- 点間候補は道路・段差・横断・閉鎖時間を見ていない
- 音声、ダイアログ、CSP、地図遷移のiOS・Android実機確認がない
- オープンデータの公開時帰属文を確定していない

### 事業仮説として未検証

- ステッカーが既存の街区表示板より早く見つかるか
- QRを読めない人に住所印字が十分か
- 家族・支援者・ホテルの誰が事前登録を担うか
- 1,242候補の偏りが実際の需要地点と合うか
- 設置、点検、撤去を継続できる主体と費用があるか

未実施:

- iOS Safari実機
- Android Chrome実機

これらは成功扱いにせず、`TASKS.md` の `MQR-008` 以降で追跡する。

## 7. 判定

| 利用 | 判定 | 条件 |
|---|---|---|
| ローカル審査デモ | 可 | `demo.html`を使う |
| 通常プロトタイプの開発確認 | 条件付き可 | 実番号を押さず、候補地表示を理解した担当者のみ |
| 公開URLでの一般デモ | 保留 | 実機確認とライセンス表示確定後 |
| 実在店舗へのQR設置 | 不可 | Phase 1の台帳・同意・不変IDが必要 |
| 一般利用者への帰路案内 | 不可 | Phase 2の現地検証済み経路が必要 |
