# 仮説検証 (docs/hypothesis-validation)

作品の前提になっている仮説と、それを確かめた記録の置き場。

`docs/research/` が「世の中で何が分かっているか」を集める場所なのに対して、
ここは「**この作品の前提が本当に成り立つのか**」を自分たちで確かめた結果を置く。
外部の文献ではなく、手元のデータと実測が入る。

## 何を置くか

| 置く | 置かない |
| :-- | :-- |
| 仮説と、それが崩れたら作品が成り立たなくなる理由 | 一般的な業界動向（→ `docs/research/`） |
| 検証の設計（何を測れば白黒つくか） | 未検証のまま断定した主張 |
| 使ったデータの出典URLと取得日 | 出典のない数字 |
| 検証コードと再現手順 | 手作業でしか出せない結果 |
| 結果（**仮説が否定された記録も残す**） | 都合のいい結果だけ |

## 命名

`YYYYMMDD-<kebab-case-の内容>.md`（`docs/research/` と同じ）。
仮説が増えたら `h01-<短い名前>/` のようにディレクトリで束ねる。

## 1件の書き方

```markdown
# H0x: <仮説を1文で>

- 状態: 未検証 / 検証中 / 支持された / 否定された
- 検証日:
- この仮説が崩れると: <作品のどこが成り立たなくなるか>

## 検証の設計
何を測れば白黒がつくか。判定の閾値を先に書く（結果を見てから決めない）。

## 使ったデータ
| データ | 出典URL | 取得日 | ライセンス |
| :-- | :-- | :-- | :-- |

## 再現手順
コマンド1行から。

## 結果
数字をそのまま。解釈は次の節に分ける。

## 分かったこと・分からなかったこと
確かめられていないことは「未検証」と書く。
```

## 決めていること

- **閾値は測る前に書く。** 結果を見てから基準を動かさない
- **否定された仮説を消さない。** 状態を「否定された」に変えて残す。捨てた数がそのまま検討の幅になる
- **数字には必ず出典URLと取得日を付ける。** 二次情報のまま書かない
- **このリポジトリは公開。** 個人名・連絡先・非公開の第三者情報は置かない
