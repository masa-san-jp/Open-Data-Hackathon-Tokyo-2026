## 1. 結論

**既存のG1〜G10を詳細化したバックログとしては、網羅性が高い。SILVERPUNK // 2100の都市構想全体を実現する総合要件定義としては、網羅的ではない。**

判定を分けると次のとおりである。

| 判定対象 | 判定 | 理由 |
|---|---|---|
| 上位文書にある77下位課題の展開 | 合格 | 77課題を引き継ぎ、G7の継続資金を追加して78課題としている |
| 各課題の記述形式 | 合格 | 全課題に「あるべき姿・現状・ギャップ・解決方法・実行方法・完了条件」がある |
| 横断的な権利・評価・責任・停止設計 | おおむね合格 | C1〜C8で本人選択、ベースライン、出典、RACI、苦情、中止等を扱う |
| SILVERPUNK都市構想の全機能領域 | 不合格 | 住環境、介護・福祉、世代間コミュニティ、環境、基幹インフラ、防災、公平性、行政財政等が独立要件化されていない |
| 現状認識の証拠追跡性 | 不合格 | 86項目の「現状」に個別の出典・取得日・証拠状態がない |
| 完了条件の検証可能性 | 要改善 | 成果物の存在確認はできるが、数値閾値、品質基準、評価方法が不足する |
| 実行管理可能性 | 要改善 | 課題別の責任者、期限、依存関係、予算・工数、ステータスがない |
| ハッカソン用の論点整理 | 合格 | 実装対象と非対象、PROOF MAPへの接続が明確である |

したがって、現状のタイトルのまま「SILVERPUNK // 2100のギャップをすべて閉じる詳細要件」と読ませると過大である。文書の役割を **「既定G1〜G10のパイロット要件バックログ」** に限定するか、後述する不足領域を追加する必要がある。

## 4. 網羅性が高い部分

### 4.1 上位77課題の欠落がない

上位の課題分解にあるG1〜G10をすべて引き継ぎ、短縮版でのみ明示されていたG7の資金調達をG7-6として補完している。この意味では、上位文書に対する縦方向の追跡性は保たれている。

### 4.2 課題が成果物と次アクションに近づいている

各課題に「どうやってやるか」と「完了条件」があり、調査テーマの列挙から、質問票、データ辞書、契約書、職務カード、実証計画、事故対応等の成果物へ進んでいる。特にG1-2の現行法内パイロット、G2-3の離脱保障、G3-6の安全側縮退、G8-8とC8の中止条件は、楽観的な未来構想に偏らない設計として強い。

### 4.3 横断課題の選び方がよい

C1〜C8は、対象範囲、本人選択、ベースライン、データ辞書、責任、苦情、公共性、停止判断を押さえている。技術導入だけでは解けない論点を独立させた点は妥当である。

### 4.4 ハッカソンスコープとの境界が明確

78課題すべてを実装しないこと、PROOF MAPでは地区・施設・経路・業務・証拠・中止条件までを扱うこと、本実装しない領域を明記している。ハッカソン成果物の過剰スコープを防ぐ文書としては有効である。

## 5. 根本的な問題：10領域の分類自体が網羅的ではない

G1〜G10は同じ分類階層にない。

| 種類 | 現在の領域 | 性質 |
|---|---|---|
| 制度・事業の実現手段 | G1制度、G3データ、G8資本 | イネーブラー |
| 市民向けサービス | G2労働、G5医療、G10移動・翻訳 | サービス領域 |
| 技術手段 | G4アシスト | 複数サービスにまたがる技術 |
| 社会的価値・成果 | G6文化 | 目標・評価領域 |
| プログラム資産 | G7記憶、G9ブランド | コンテンツ・IP・市場形成 |

制度、サービス、技術、成果、IP資産を同じ階層に並べているため、分類は **MECEではない**。各領域をどれだけ細かくしても、上位分類にない「住宅」「介護」「環境」「基幹インフラ」等は出てこない。対象文書の不足は、78項目の掘り下げ不足よりも、元となる10領域の分類不足に起因する。

### G12 介護・福祉・地域生活・コミュニティ

- 地震、火災、洪水、高潮、土砂、感染症等の複合シナリオ

### G15 公平性・包摂・人口・分配

- 年齢、性別、障害、所得、国籍、言語、世帯、地域別の効果と負担
- デジタルを使えない・使わない人への同等手段

### G16 行政財政・公共調達・運用能力

## 9. 現行86項目の要件品質上の不足

### 9.1 「現状」が証拠ではなく記述になっている

現状欄は妥当な問題提起を含むが、出典、基準日、対象地域、データの品質、確認済み・仮説・未確認の区分がない。現在の文章だけでは、現状が変わった時に差分を更新できず、立法事実や投資判断の証拠にも直接使えない。

各現状欄に最低限、次を追加する必要がある。

- `evidence_id`
- 出典URLまたは現地調査記録
- 取得日・対象期間・対象地域
- 実測／推計／代理指標／専門家判断／未確認
- データ品質と欠損
- 反証または代替説明

### 9.2 完了条件が「成果物がある」に止まる

「一覧がある」「説明できる」「決まっている」は成果物の存在条件としては有効だが、品質の合否を判断できない。例えば同意書が存在しても、当事者が理解できなければ要件は達成していない。

完了条件は次の4層に分けるべきである。

1. **成果物**: 何が存在するか
2. **品質**: 正確性、完全性、アクセシビリティ、安全性
3. **結果**: 利用者・現場で何が変わったか
4. **判定閾値**: 継続、修正、中止を分ける数値または明示的基準

### 9.3 2100年の最終状態とパイロット状態が混在する

文書冒頭で「2100年またはパイロット段階」としており、同じ「あるべき姿」に異なる時間軸が混在する。パイロットで1件復元できることと、2100年に都市規模で持続することは別要件である。

各課題を少なくとも次に分ける必要がある。

- 最終アウトカム（2100）
- フェーズ成果（2035、2055、2080）
- 次のパイロット受入条件（2026〜2031）

### 9.4 解決策が先に固定されている項目がある

Data Trust、SPV、FHIR、限定ODD等は有力な候補だが、課題定義と解決策候補が同じ欄で固定されている。代替案、選定基準、採用しない条件を残さなければ、仮説検証ではなく構想の正当化に偏る。

### 9.5 横断要件が再掲され、参照関係がない

本人の離脱、データ撤回、事故対応、中止条件は複数領域に繰り返し登場する。内容自体は必要だが、共通要件C2・C6・C8を親要件とし、各G項目では追加差分だけを記述しなければ、更新時に内容が不整合になる。

### 9.6 優先順位の根拠が監査できない

全体優先順位は示されているが、影響度、緊急度、不可逆性、依存関係、実現可能性、費用、証拠不足等の評価値がない。G7を最優先とする時間切れ判断は理解できるが、都市パイロットのクリティカルパスとは別ポートフォリオとして管理した方がよい。

| 交通・移動 | 高 | G4・G10で具体化されている |
| 市民参加・雇用・尊重 | 高 | G2・G6・C2で強く扱う |
| 情報・コミュニケーション | 中〜高 | G3・G7・G10で扱うが、日常情報アクセスとデジタル排除は薄い |
| 保健 | 中〜高 | G5は研究・臨床・国際患者に強い |
| 地域支援・介護 | 低 | 介護、在宅支援、家族支援、看取りが独立していない |
| 住宅 | 低 | WHO・ISO・SDG 11で中心領域だが、独立要件がない |
| 屋外空間・建築 | 低〜中 | 1経路の環境改善はあるが、公共空間・建築・土地利用の体系がない |
| 教育 | 低 | 技能継承以外の生涯学習、人材育成、子ども・若者教育が薄い |
| エネルギー・水・廃棄物・食 | 低 | 都市サービスとしてほぼ未定義 |
| 気候・災害・基幹インフラ | 低 | サービス単位の縮退はあるが、都市レジリエンス計画がない |
| 行政財政・公共調達 | 低 | 民間資本設計はあるが、公費・税・社会保障・調達・TCOが薄い |
| 属性別公平性 | 低〜中 | 本人選択と公平性の理念はあるが、属性別の測定・是正がない |

## 11. 推奨する再構成

単純にG11〜G16を末尾へ追加するより、次の4層に再編した方が、重複と欠落を同時に減らせる。

| 層 | 内容 | 主な構成 |
|---|---|---|
| L0 成果 | 都市が実現する価値 | 自律、健康、安全、所得、参加、尊厳、所属、公平性 |
| L1 市民サービス | 暮らしの機能 | 住宅・公共空間、介護・医療、労働、移動、教育・文化・記憶、情報、来訪体験 |
| L2 実現基盤 | サービスを成立させる手段 | 制度、行政財政、資本、データ・AI、アシスト技術、都市OS、人材、調達 |
| L3 保証 | 不利益と失敗を制御する仕組み | 権利、公平性、倫理、安全、防災、サイバー、証拠、監査、継続・撤退 |

既存G1〜G10は廃棄せず、この4層へ再マッピングする。これにより、G3データとG4アシストをサービス領域と混同せず、G7記憶とG9ブランドを都市基盤と混同せずに管理できる。

## 13. 改訂優先順位

### P0：網羅性を名乗る前に必要

1. 文書スコープを「既定G1〜G10」に限定するか、「都市構想全体」に拡張するか明記する。
2. G11住環境、G12介護・地域生活、G13環境・基礎サービス、G14防災、G15公平性、G16行政財政・調達を追加する。
3. 4層モデルで既存G1〜G10との重複・親子関係を整理する。
4. 全86項目に上位目的と元資料の対応IDを付ける。

### P1：実行可能にするために必要

1. 全「現状」に出典、基準日、証拠区分を付ける。
2. 完了条件へ品質基準、結果指標、Go/Modify/No-Go閾値を追加する。
3. 責任者、承認者、期限、依存関係、工数・予算を付ける。
4. 2026パイロットと2100最終状態を分ける。
5. シナリオ、反証条件、代替案を明記する。

### P2：運用・更新に必要

1. 共通要件をC系列へ正規化し、各G項目は参照＋差分にする。
2. 要件カバレッジ表を自動検査できる形式にする。
3. 現地調査、法務確認、当事者レビュー、データ更新で状態を更新する。
4. PROOF MAPから未解決要件・担当者・期限・証拠へ遷移できるようにする。
