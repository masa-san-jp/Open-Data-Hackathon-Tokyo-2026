## 2. スコープ候補 ― 課題P0〜P6から「2日で動くもの」を切り出す

各候補に、**東京都ODカタログ全9,678件（2026-07-04取得）に対するキーワード実測**を添えた。
実測コマンドは §5。数字は「タイトル＋概要」への部分一致件数であり網羅ではない。

### 候補A: パイロット候補地スコアリングマップ（P1/D3 直結）

戦略書 Year 0-1 の意思決定事項 **D3「パイロット候補地の選定」** をオープンデータで支援する。
5基準（高齢者コミュニティ密度／空き店舗率／自治体の特区意欲／交通アクセス／温泉・銭湯等資源）を
区市町村単位でスコアリングし、候補地ロングリストを機械生成する。

| 必要データ | カタログ実測 | 判定 |
| :-- | --: | :-- |
| 人口・住民基本台帳（高齢者密度） | **936件**（総務局555） | ◎ 潤沢 |
| 高齢者・高齢化 | 129件 | ○ |
| 交通・バス・駅 | 215件 | ○ |
| **空き家・空き店舗** | **0件** | ✕ **ODに存在しない** |
| 商店街 | 3件 | ✕ ほぼ無い |
| 公衆浴場・銭湯 | 8件（港区4など区単位で散発） | △ 薄い |
| 温泉 | 1件（八丈町のみ） | ✕ |

**含意**: 5基準のうち2つ（空き店舗・地域資源）が公式ODで測れない。
→ 弱点ではなく主張に転換できる: **「候補地選定に必要なデータの半分が公開されていない」を欠損マップとして見せる**。
7/26の補助金実測（未一致193件=1,284億円）と同じ「追えないものを見せる」型が地理データでも成立する。

### 候補B: 職住医福 到達性マップ（UAD Dアプローチ選定支援）

UAD概念整理の実証手法 **「D: 単一動線集中型＝最頻経路1本を完全UAD化」** の対象動線を選ぶための、
到達性（住居→医・福・職・店への実所要）の可視化。最重要KPI「断念率」の測定設計の土台になる。

| 必要データ | カタログ実測 | 判定 |
| :-- | --: | :-- |
| 医療機関・病院 | 72件 | ○ |
| 介護・福祉施設 | 121件 | ○ |
| 公園・トイレ（休憩インフラ） | 220件 | ○ |
| バリアフリー | **13件** | △ 環境層データが薄い＝これも欠損の証拠 |
| 熱中症・暑さ対策（気候×移動） | 3件 | ✕ |

**含意**: 施設の「点」データはあるが、UAD層1（環境: 段差・屋根・ベンチ間隔）の「線」データがほぼ無い。
点データで到達性のベースラインは作れる。

### 候補C: 転入ゼロ×2100 東京シミュレータ（視界切れを埋める）

一次情報調査で確定した事実 **「東京都の2100年人口には現行の公式単一値が存在しない。公的推計は2050/2065年で切れる」** への直接の応答。
**実装資産が既にある**: `docs/concept-research/20260822-tokyo-zero-inflow-cohort.py`（コーホート要因法・公式ソースを実行時取得・CSV出力済み）。

| 必要データ | カタログ実測 | 判定 |
| :-- | --: | :-- |
| 人口・住民基本台帳・人口移動 | 936件 | ◎ このためにあるような厚み |

**含意**: 当日の作業は「計算コードを対話UI化し、シナリオ（転入ゼロ／半減／出生率変動）を都民が動かせるようにする」に絞れる。
2日の博打が最も少ない。審査基準③（技術難度）に人口学の手法（コーホート要因法）で答えられる。

### 候補D: 記憶アーカイブ優先度マップ（P0 時間切れ型）

戦略書の最優先課題 **P0「記憶の緊急アーカイブ」（2026〜2032・不可逆）** の対象特定。
銭湯・商店街・伝統工芸など「消えつつある演目資源」の残存分布と消滅速度をODで可視化する。

| 必要データ | カタログ実測 | 判定 |
| :-- | --: | :-- |

**含意**: 主題の緊急性は最も高いが、**ODの供給が最も薄い**。単独では審査基準①が立ちにくい。
候補Aの欠損マップに「時間切れ型の欠損」として統合する方が筋が良い。

## 4. 組み合わせパターン（推奨の並び）

**一つに絞らない**前提で、核＋レイヤの構成にする。

| 案 | 構成 | 一言 |
| :-- | :-- | :-- |
| **案1（推奨）** | **C を核 ＋ A をレイヤ** | 「2100年の東京を自分で動かせる」シミュレータの上に、「では、どこから始めるか」の候補地スコア（欠損表示付き）を重ねる。**現状（視界切れ）→未来（2100）→取り組み（候補地）が1画面で繋がる** |
| 案2 | A を核 ＋ D を欠損レイヤ | 候補地選定マップに徹する。D3意思決定に最短だが、2100との接続が言葉頼みになる |
| 案3 | C 単独 | 最も安全。ただし「SILVERPUNKの入口」としての固有性が薄れ、人口シミュレータ一般に見えるリスク |
| 非推奨 | B 単独 | 経路計算・地図実装が2日に対して重い。到達性はFirst Stage以降の拡張に回す |

## 5. 実測の再現

```bash
cd docs/research/data
python3 - '東京都オープンデータ全カタログ_9678件_20260704.csv' <<'PY'
import csv, sys
rows = list(csv.DictReader(open(sys.argv[1], encoding='utf-8-sig')))
kws = ["高齢者","空き家","空き店舗","商店街","公衆浴場","銭湯","人口","バリアフリー"]
for k in kws:
    n = sum(1 for r in rows if k in (r['タイトル'] or '') + (r['概要'] or ''))
    print(f"{k}: {n}件")
PY
```

注意: キーワード部分一致による概数。ヒット0件は「その語を含むデータセットが無い」ことを示すのみで、
類義語・別表記での存在可能性は排除できない（例: 空き家は「住宅・土地統計調査」内の項目としては存在する）。
