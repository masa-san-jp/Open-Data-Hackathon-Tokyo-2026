---

## 1. 結論サマリー

- **単機能サービス領域（見守り・MaaS・介護ロボット・PHR・シニア就労マッチング・デジタルデバイド）は完全なレッドオーシャン**。ここへの新規単体参入では差別化はほぼ不可能。
- 一方で **G7（記憶＝高齢者の記憶・技能のIP／公共資産化）、G16（行政財政＝事業撤退・データ引継ぎ設計）、G15（公平性＝属性別の是正措置）、および領域横断の「地区統合＝Ageing District Stack」はほぼ空白**。
- 空白領域は「未着手だから空白」ではなく、**継続資金・制度的インセンティブ・データ標準が欠けているために誰も定着させられていない構造的空白**。これは実証が「作って終わり」になりやすい東京都オープンデータ文脈の弱点と一致する。
- 最も勝ち筋があるのは、既存の単機能サービス（見守り・移動・就労）を**地区単位で束ねる統合レイヤー**と、**実証後に事業者が撤退してもサービス・データ・機器が引き継がれる出口設計**。
- 都知事杯オープンデータ・ハッカソンでは過去5回（2021〜2025年度）で**認知症・高齢者介護を主対象とした受賞作が1件も確認できず**、この文脈でも空白が明確に存在する。

---

## 2. 主要な発見

1. **対象ドキュメントは「10領域はMECEでない」と自己批判している。** G1〜G10は制度・サービス・技術・成果・IP資産が同一階層に混在し、住宅・介護・環境・防災・公平性・行政財政が抜け落ちていると明記。追加すべき6領域（G11〜G16）を自ら提案している。したがって空白領域の探索は、ドキュメント自身が示すG11〜G16と横断課題（Ageing District Stack）に集中させるのが合理的。

2. **レッドオーシャン領域には共通して「実証は多いが継続しない」問題がある。** MaaSは国交省が令和元〜7年度で累計約119事業を選定・支援したが多くが実証で終息。介護ロボットは2012年からの国策で製品・補助金が飽和。見守りGPSは全国の自治体が個別に貸与事業を乱立させ、標準化・広域連携が欠落。

3. **「記憶（G7）」は海外にスタートアップが集積するが、日本の公共文脈では空白。** Autograph AI、Sensay、Inalife、エストニアのライフストーリー企業など「デジタルレガシー経済」が海外で立ち上がる一方、日本では高齢者の記憶・技能を都市／地域の資産として制度的に扱う公共モデルが見当たらない。製造業の「匠AI」型技能継承はあるが対象が企業内資産に限定。

4. **行政財政・撤退設計（G16）と属性別公平性（G15）はほぼ完全な空白。** 事業者撤退・倒産時のサービス／データ／機器の引継ぎ、ライフサイクルコスト、属性別（所得・国籍・地域別）の便益と負担の測定・是正を扱う先行事例が国内外を通じてほとんど見当たらない。

## 3. 対象ドキュメントの領域構成（精読結果）

SILVERPUNK // 2100 は超高齢社会を前提とした2100年ターゲットの都市構想。既存10領域と追加提案6領域は以下のとおり。

| ID | 領域 | ドキュメント上の位置づけ |
|---|---|---|
| G1 | 制度 | イネーブラー（制度・事業の実現手段） |
| G2 | 労働 | 市民向けサービス |
| G3 | データ | イネーブラー |
| G4 | アシスト技術 | 複数サービスにまたがる技術 |
| G5 | 医療 | 市民向けサービス |
| G6 | 文化 | 目標・評価領域 |
| G7 | 記憶 | プログラム資産（コンテンツ・IP） |
| G8 | 資本 | イネーブラー |
| G9 | ブランド | プログラム資産 |
| G10 | 移動・翻訳 | 市民向けサービス |
| G11（追加提案） | 住環境・都市空間 | 欠落（WHO/ISO/SDG11で中心領域なのに未定義） |
| G12（追加提案） | 介護・福祉・地域生活・コミュニティ | 重大な不足 |
| G13（追加提案） | 環境・資源・基礎サービス | ほぼ未定義 |
| G14（追加提案） | 防災・基幹インフラ・都市レジリエンス | サービス単位の縮退のみ |
| G15（追加提案） | 公平性・包摂・人口・分配 | 属性別測定・是正がない |
| G16（追加提案） | 行政財政・公共調達・運用能力 | 公費・税・調達・TCOが薄い |

同文書は横断課題としてC1〜C8（本人選択、ベースライン、責任、苦情、停止判断等）を評価し、さらにC9トレーサビリティ〜C15公平性影響評価の追加を提案。また「**Ageing District Stack**（住宅・モビリティ・健康・雇用を束ねた地区統合）」が個別要素はあるが統合アーキテクチャがない、と指摘している点が本調査の核心的な空白示唆となる。

### G1/G11/G13/G15/G16 — 混雑度: ⚪ 大部分が空白〜不十分

- **G11 住環境**: ユニバーサルデザイン住宅・空き家活用・職住医福近接は個別施策は存在するが、対象ドキュメントも「WHO/ISO/SDG11で中心領域なのに独立要件がない」と指摘。高齢者向け住宅供給×健康モニタリング×監視拒否権を束ねた統合事例は**先行事例を確認できず**。
- **G13 環境・資源**: 猛暑・エネルギー・水・廃棄物・買物アクセスを高齢者都市サービスとして扱う統合事例は**先行事例を確認できず**（単発の熱中症マップ等はハッカソンにあるが都市サービス化されていない）。
- **G15 公平性**: 属性別（所得・国籍・言語・地域別）の便益・負担の測定と是正措置を行う仕組みは国内外でほぼ**空白**。デジタルデバイド対策は入口だが是正措置までは届いていない。
- **G16 行政財政・撤退設計**: 事業者撤退・倒産時のサービス／データ／機器の引継ぎ、ライフサイクルコスト、ベンダーロックイン回避の設計は**先行事例を確認できず**。実証が「作って終わり」になる東京都オープンデータ文脈の弱点と直結する最大級の空白。

参考: 東京都デジタルデバイド解消事業（令和8年度予算11億円、65歳以上のスマホ初購入に最大3万円助成、東京アプリ登録が条件）は**レッドオーシャン**の入口領域。
出典: https://www.digitalservice.metro.tokyo.lg.jp/business/digital-divide/sumahojo

## 6. 推奨アクション（判断材料）

### ステージ1: 避けるべきもの（即時判断）
単機能の見守りアプリ・MaaS・介護ロボット・PHR・シニア就労マッチング・スマホ教室型デジタルデバイド支援は完全なレッドオーシャン。単体では着手しない。都知事杯でも移動・バリアフリー系は既に受賞作が集中している。

### ステージ2: 狙うべき空白（優先投資）
1. **地区統合レイヤー（Ageing District Stack）** — 既存の見守り・移動・就労・医療データを「地区単位」で束ねるダッシュボード／データ契約。既存サービスと競合せず補完する立ち位置。東京都オープンデータ＋地区限定パイロットで実装可能。
2. **G16 出口設計（撤退・引継ぎ）** — 「実証事業者が撤退してもサービス・データ・機器が引き継がれる」標準仕様・エスクロー・データトラスト。東京都オープンデータ文脈の最大の弱点（延べ37実装のうち多くが単発）を直接解く公共価値が高い。
3. **G7 記憶の公共資産化** — 高齢者の記憶・技能を地域IP／生涯学習教材として蓄積するモデル。海外スタートアップ（Autograph等）の技術は既にあるので、日本の「公共・継続資金・同意管理」の側を設計する。

### ステージ3: 条件付き
認知症village型の街区統合（G11×G12）は投資規模が大きく撤退リスクも実証済み（豪Emmaus Villageのコスト超過等）。いきなり物理街区ではなく「デジタル上の認知症フレンドリー地区」から始める。

### 判断を変える閾値
- (a) 東京都が2026年度ハッカソンのテーマに「高齢者・介護」を明示採用した場合 → G12統合の受賞可能性が上がるため優先度を上げる
- (b) 対象ドキュメントのG7継続資金（G7-6）の具体的スキームが固まらない場合 → G7は撤退し地区統合（横断）に一本化
- (c) 台湾・シンガポールが同型の統合モデルを東京に持ち込む動きが出た場合 → 出口設計（G16）に特化して差別化

## 7. 調査の限界（Caveats）

- 「ほぼ空白」判定は日本語・英語の網羅検索に基づくが、非公開の実証・大学の未公表プロジェクト・直近立ち上げのスタートアップは捕捉できていない可能性がある。「先行事例を確認できず」は「存在しない」ことの証明ではない。
- リポジトリ内の関連文書（gap-decomposition、task-breakdown、urban-concept-research等）はGitHubのアクセス制約で直接取得できず、領域構成は検証レポート本体の記述から再構成した。G1〜G16のラベルは同レポートに明記されているが、各領域の細目解釈には推測が含まれる。
- 数値には時点差がある。都知事杯の「実装サービス数」は2024年8件→2025年10月28件→2026年6月37件と累計で変動。MaaS事業数は年度別選定の合算値であり稼働継続数ではない。Hogeweykの居住者数は資料により152〜188名と幅がある（拡張の時点差）。
- 事実（出典URL付き）と推測（本レポートの評価・混雑度判定・推奨）は区別している。混雑度と推奨は調査に基づく判断であり、意思決定の材料として扱われたい。
