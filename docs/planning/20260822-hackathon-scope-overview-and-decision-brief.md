### 1-2. 未来像（SILVERPUNK // 2100）

「老い」を都市最大の輸出資源に転換する都市国家型テーマパーク。体験価値・医療価値・データ知財価値の三位一体で、職住医福が徒歩圏＋無人モビリティ圏で完結する。物理層を支えるのが「ユニバーサルアシストデザイン(UAD)」＝環境・機器・情報の三層が能動的にアシストする設計思想。戦略書が掲げる定量目標は、特区での年間来訪者3,000万人（海外6割）、高齢就労者50万人、医療ツーリズム年間50万人、健康寿命+10年。

### 1-3. ギャップ（10領域・3類型）

README のG1〜G10表がそのまま最も整理された形。要点は、**時間切れ型はG7「記憶」のみ**（昭和世代の技能・語りが今まさに失われつつあり、待つほど不可逆）、**実証不足型が6領域**（制度・労働・医療・文化・資本・ブランド＝技術やお金はあるが「証拠」がない）、**技術成熟待ち型が3領域**（データ統合・アシスト機器・モビリティ翻訳＝市場が進めば解消しうる）という3分類。加えて仮説検証ドキュメント側からは、UADの「層1(環境)・層3(情報)が未整備なまま層2(機器)だけ入れると『使えるが呼べない設備』になる」という、より実装レベルのギャップも確認できた。

### 1-4. 課題（P0〜P6、優先度順）

**P0 記憶の緊急アーカイブ**（2026〜2032・不可逆・最優先）を筆頭に、P1パイロット地区での就労×医療統合実証、P2誇りの労働ナラティブ構築、P3特区制度設計、P4資本スキーム、P5ブランド先行占有、P6技術要件標準化と続く。仮説検証ドキュメント側で追加確認できた横断的な論点は、データ倫理・労働者のオプトアウト権、稼働不安定性への備え（多能工化・予備人員）、単発のノスタルジー観光は赤字化しやすい（西武園100億円投資も赤字、ハウステンボスは一度破綻）という収益モデルへの警鐘。

### 1-5. 取り組み（Phase1〜4）

Phase 1 PROOF（2026-2035・数ha規模のパイロット1〜2箇所・キャスト100〜500名）→ Phase 2 ZONE（特区指定）→ Phase 3 CITY（都市統合）→ Phase 4 OVERDRIVE（メソッド輸出）。**本ハッカソンの作品はPhase 1 PROOFの入口**と位置づけられている（README「本ハッカソンでの位置づけ」）。直近5年プランでは2026-2027にパイロット候補地の選定（D3）と記憶アーカイブの先行開始が並走する。

## 2. 既存のスコープ候補（`docs/planning/` 側で整理済み）の再検証

`20260822-hackathon-scope-selection-prep.md` は東京都オープンデータカタログ全9,678件のキーワード実測付きで候補A〜Eを既に比較済み。9本の仮説検証ドキュメントを通読した結果との照合は以下の通り。

| 候補 | 既存の判定 | 全文読了後の追加所見 |
| :-- | :-- | :-- |
| **A: パイロット候補地スコアリング** | ◎データ活用／P1・D3に直結 | 柏の葉の実例（満足度は高いがコミュニティ・介護満足度は低い、車依存52%）は「候補地スコアに“定量では見えないリスク”がある」ことの裏付け事例として使える。スコアだけで決め切らない注記を画面に添えると審査基準⑤に効く。 |
| **B: 職住医福 到達性マップ** | △経路計算が重い | UAD概念整理の最重要KPIは「断念率」（行こうとしてやめた回数）。これは実測が要るため2日では測れず、既存判定「2日に対して重い・非推奨」は妥当と再確認。 |
| **C: 転入ゼロ×2100シミュレータ** | ◎実装資産あり・最有力 | 仮説検証ドキュメント側で追加の定量分解が取れた：2100年時点で国内転入ゼロの影響（累積-1,268.2万人）は国外転入ゼロの影響（累積-235.0万人）の**約5.4倍**。UIで「国内転入」「国外転入」を独立トグルにすると、この非対称性がそのまま画面上の発見になり、審査基準②（アプローチの秀逸性）を強められる。 |
| **D: 記憶アーカイブ優先度マップ** | △ODが薄く単独では不成立 | 先行事例調査で上勝町「いろどり」（葉っぱビジネス、年商2.6億円）等の具体事例が確認できた。単独候補としてではなく、候補Aの欠損レイヤ、または画面内の「P0是不可逆」という文言の説得力補強に使うのが妥当という既存の結論を支持。 |
| **E: 高齢就労エビデンス基盤** | △形になりにくい | 先行事例調査のGBER（高齢者ジョブマッチング、シルバー人材センター会員68万人）は属性レイヤとしての具体例になる。単独候補には不向きという既存判定を支持。 |

### 検討したが採用を見送るべき候補F: 「Care & Work OS」型 AI HaaSマッチングUI

労働力誘致インフラ調査・都市コンセプト調査の両方で最優先施策として名前が挙がる「AIが候補を提示し本人が承認する高齢者向けシフト/求人マッチング」は、コンセプトとしての説得力は高い。しかし、個人の職務適合・健康制約・希望条件はそもそも東京都オープンデータに存在しない領域であり、審査基準①（データ活用の有効性）が立ちにくく、UIモックで終わるリスクが高い。Phase 1 以降（制度・データガバナンスが整った段階）向けの構想として保留するのが妥当。

## 3. 組み合わせパターンの再確認と設計への追加提案

既存の§4「組み合わせパターン」（案1推奨：C核+Aレイヤ／案2：A核+Dレイヤ／案3：C単独／非推奨：B単独）はそのまま妥当と判断する。追加提案は1点。

**候補Cの画面設計に「国内転入シナリオ」「国外転入シナリオ」を独立トグルで持たせる。** 上記の通り国内転入の影響が国外転入の約5.4倍という非対称性は、東京の人口・出生・労働力が「20代の国内純流入」に強く依存している構造（国内転入の51.8%を20代が占める）と整合する事実であり、README §1の「視界切れ」問題（東京都の2100年人口に公式値がない）に対して、単なる延長推計ではなく「何が効いているのか」まで見せる回答になる。これは審査基準②③④のいずれにも波及する設計上の強化ポイント。

## 4. 残っている意思決定事項（オーナー判断）への材料

`docs/planning/` の§6に挙がっている4項目について、判断材料を補強する。**最終判断はオーナー。**

### (1) 案1〜3のどれで行くか

案1（C核+Aレイヤ）を推奨する追加根拠は上記の通り。リスクとして唯一残るのは「地図実装（候補Aのレイヤ表示）に工数を取られてCのシナリオUIが薄くなる」こと。もし2日目午前の時点でA側の地図実装が重くなっていたら、**候補Aは地図なしの表（区市町村ランキング表＋欠損マップの静的画像）に格下げして案3寄りに倒す**、というフォールバック条件を先に決めておくと当日の判断が速い。

### (2) 核に据える問い

候補案（いずれもC×Aの設計と整合）:

- 「転入がゼロになった東京で、最初のパイロット地区はどこに置くべきか」
- 「東京の人口を動かしているのは国内か、海外か——2100年から逆算する」

### (3) 作品名

コンセプトに沿う候補（いずれも仮称、選定はオーナー判断）:

- TOKYO BACKCAST 2100
- SILVERPUNK LAUNCHPAD
- 視界の切れ目、東京2100

### (4) 地図基盤の選定

候補Aのレイヤ表示に使う地図データの比較。

| 選択肢 | 特徴 | 2日実装での向き不向き |
| :-- | :-- | :-- |
| 国土数値情報 N03（行政区域データ、国交省） | 区市町村ポリゴンのShapefile/GeoJSON。`mapshaper`等で軽量化してWeb表示するノウハウが確立している | 向いている。区市町村単位のコロプレス（塗り分け）マップに必要十分で、当日の実装コストが低い |
| PLATEAU | 3D都市モデル（CityGML中心）。建物単位の精緻なデータだが3D表示・変換の学習コストが高い | 今回の粒度（区市町村スコアリング）には過剰。3D表現が審査基準⑤の見栄えに寄与する場面があれば検討の余地はあるが、2日間の主目的には不向き |

区市町村単位のスコアリング・欠損マップという候補Aの用途には、国土数値情報N03を軽量化して使う方が2日間の実装リスクが低い。
