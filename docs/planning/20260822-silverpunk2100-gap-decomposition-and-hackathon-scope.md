# SILVERPUNK // 2100 — 10領域ギャップ分解・下位課題一覧

作成日: 2026-08-22  
対象: `masa-san-jp/Open-Data-Hackathon-Tokyo-2026/docs/concept-research`  
目的: 現状→未来→ギャップ→課題→取り組みを、実証・設計・制度化へ進められる単位まで分解する

## 1. 分解の前提

前回の整理は、10領域のギャップからP0〜P6の大きな取り組みへ飛びすぎていた。ここでは、各ギャップを次の4層に分ける。

1. **ギャップ**: 2100年の到達状態と2026年の状態の差
2. **根本課題**: 差を生んでいる構造的な詰まり
3. **下位課題**: 一つずつ調査・設計・合意・実証して潰す対象
4. **完了条件**: 「考えた」ではなく、次の判断に使える証拠・成果物

タグの意味:

- `[定義]` 対象範囲・役割・成功状態を決める
- `[合意]` 本人、住民、労働者、行政、医療機関などの同意を得る
- `[法務]` 現行法で可能か、特例・改正が必要かを確定する
- `[設計]` サービス、データ、施設、業務を具体化する
- `[実証]` 小さく運用して事実を得る
- `[運用]` 事故、離脱、保守、苦情などの継続管理を決める
- `[評価]` KPI、比較方法、継続・中止基準を決める

## 2. 10領域の全体像

| 領域 | 根本ギャップ | 最初にクリアすべきゲート | 優先度 |
|---|---|---|---|
| G1 制度 | 包括特区を動かす立法事実がない | 現行法内で成立する1地区の実証範囲を確定する | 高 |
| G2 労働 | 働く・休む・療養するを往復する就労設計がない | 1職種・1業務の短時間就労を、権利保護込みで定義する | 最優先 |
| G3 健康データ | 部品はあるが、目的別データ連携と即応責任がない | 生データを雇用主へ渡さず、1ユースケースの安全な連携を実証する | 高 |
| G4 アシスト | 高齢者が日常的に使える環境・機器の組み合わせがない | 1本の移動・作業ルートを環境改善中心で成立させる | 高 |
| G5 医療 | 研究シーズと商用・臨床実証の間が空いている | 国内医療を圧迫しない、1テーマの臨床実証要件を定義する | 中長期 |
| G6 文化 | 高齢就労が誇りか搾取かを分ける基準がない | 本人の選択・報酬・離脱権を含む倫理憲章を先に合意する | 最優先 |
| G7 記憶 | 技能・語り部が失われる時間切れリスクがある | 収録対象・同意・権利処理を決め、最初の記録を残す | 即時 |
| G8 資本 | 数十年構想を支える段階的な資金回収設計がない | 1地区の事業単位経済性と、次段階の投資ゲートを示す | 高 |
| G9 ブランド | 世界観・名称・体験の先行占有がない | 本人参加型の体験プロトタイプで、何が固有かを検証する | 中 |
| G10 移動・翻訳 | 技術は進展しているが、生活圏での統合運用がない | 1つのOD・1つの翻訳場面を人間フォールバック込みで成立させる | 高 |

## 3. G1 制度 — 包括特区を成立させる

### 根本課題

医療ツーリズム、柔軟な高齢者就労、建築・データ・モビリティを一体化した「超高齢東京特区」を提案しても、現時点では、それを認める立法事実と運用責任の証拠がない。

### 下位課題

- **G1-1 `[定義]` 特区の機能を分解する**
  - 「医療」「就労」「住宅」「移動」「記憶・観光」「データ」を一つの言葉で束ねず、機能ごとに定義する。
  - 対象地区、対象者、対象事業者、対象時間、対象データを明記する。
  - 完了条件: 1地区・1施設・1移動経路を含む機能一覧と対象者・責任者マップがある。

- **G1-2 `[法務]` 現行法でできる範囲を確定する**
  - 雇用契約、短時間勤務、業務委託、ボランティア、医療滞在、個人情報、道路・車両、建築・消防を機能別に確認する。
  - 各項目を「現行法で可能」「自治体・省庁協議が必要」「特例・改正が必要」に分ける。
  - 完了条件: 法的論点の一覧に、根拠、担当機関、未確定事項、代替案が付いている。

- **G1-3 `[合意]` 行政の権限分担を決める**
  - 国、東京都、区市町村、施設管理者、医療機関、運営会社の責任境界を決める。
  - 「許可を取る相手」だけでなく、事故・苦情・データ目的外利用の最終責任者を置く。
  - 完了条件: 意思決定フローと、各判断の承認者・相談先が一枚で示される。

- **G1-4 `[実証]` 特区なしで動くパイロットを設計する**
  - 特区指定を待たず、現行法内の雇用契約、短時間就労、既存交通、既存医療連携で開始する。
  - 特区がなくても継続でき、特区があれば拡張できる二段構えにする。
  - 完了条件: 特区が未成立でも実施可能な業務手順、契約、施設、保険、緊急対応がある。

- **G1-5 `[評価]` 特区提案に必要な証拠を先に定義する**
  - 需要、安全性、就労継続、健康上の便益、地域経済、住民受容、医療アクセスへの影響を測る。
  - 「何人いれば成功か」「何件の事故なら中止か」を先に決める。
  - 完了条件: 特区申請に転用できるエビデンスパッケージの目次と測定計画がある。

- **G1-6 `[法務]` 例外を一括要求しない**
  - 就労、データ、医療、モビリティ、建築を、それぞれ解くべき制度課題として分ける。
  - 特例の期限、対象範囲、見直し条件、終了条件を付ける。
  - 完了条件: 「何を変えれば、どの機能が、どのKPIまで可能になるか」が対応表になっている。

- **G1-7 `[運用]` 監督と救済を制度に含める**
  - 独立した倫理・安全委員会、本人の苦情申立て、第三者監査、事故報告、データ利用停止を設ける。
  - 完了条件: 事故時・苦情時・同意撤回時の対応SLAとエスカレーション先が決まる。

### G1の完了ゲート

「1地区で現行法内に安全に実証できる」「その結果をどの制度変更につなげるか説明できる」「住民・労働者が拒否・離脱できる」の3点が揃うこと。

## 4. G2 労働 — 体調連動の柔軟就労を成立させる

### 根本課題

未来像は分単位・短時間・体調連動の就労だが、制度と運用は通常の雇用契約を中心に設計されている。健康情報を使って仕事を最適化しようとすると、監視・選別・不利益取扱いに直結する危険もある。

### 下位課題

- **G2-1 `[定義]` 仕事を職種名ではなく作業単位に分解する**
  - 接客、案内、語り、調理補助、記録、清掃、教育などを、時間、姿勢、移動距離、対人負荷、認知負荷で記述する。
  - 完了条件: 1職種について、作業カードと必要条件・避ける条件がある。

- **G2-2 `[法務]` 働き方の身分を分ける**
  - 雇用、業務委託、地域貢献、学習・継承、リハビリを混同しない。
  - 賃金、最低保障、労災、安全配慮、社会保険、キャンセル時の扱いを個別に定義する。
  - 完了条件: 1業務の契約・報酬・事故時責任が確定している。

- **G2-3 `[合意]` 「働かない自由」を設計する**
  - 参加・拒否・一時停止・退会を本人が選べるようにする。
  - 仕事を断ったことが、医療、年金、住居、次の仕事に不利益を与えないことを明文化する。
  - 完了条件: 同意、撤回、休止、再開の手順を本人が理解できる。

- **G2-4 `[設計]` 健康データを職務制約へ変換する**
  - 生の病歴・バイタルを雇用主へ渡さず、「連続立位は30分まで」「階段不可」など必要最小限の制約にする。
  - 本人が内容を閲覧・修正・期限設定できるようにする。
  - 完了条件: 1業務について、健康情報を使わずに同等の制約を入力できる代替方法がある。

- **G2-5 `[設計]` マッチングは候補提示＋人間承認にする**
  - 希望時間、経験、移動可能範囲、対人役割、必要な配慮を使って候補を提示する。
  - 提案理由、使ったデータ、断る方法、異議申立て先を表示する。
  - 完了条件: AIやルールが誤っても、人間が覆し、理由を記録できる。

- **G2-6 `[設計]` 仕事そのものを再設計する**
  - 8時間勤務を短時間の組み合わせへ分割し、交代、休憩、引き継ぎ、複数担当を組み込む。
  - 高齢者を安価な労働力ではなく、経験・接客・教育・継承の担い手として位置づける。
  - 完了条件: 1業務が、短時間化しても品質と収益を維持できる。

- **G2-7 `[運用]` 欠勤・急変・事故に耐える**
  - 体調による当日キャンセル、代替要員、緊急退避、医療連携、労災対応を決める。
  - 完了条件: 1件の欠勤や急変でサービスが止まらない運用手順がある。

- **G2-8 `[評価]` 成功を稼働時間だけで測らない**
  - 就労継続率、自己決定率、収入の安定、疲労、事故、満足度、参加後の社会的つながりを測る。
  - 完了条件: 「働かせた人数」ではなく、「本人が選び、無理なく続けられたか」を示せる。

### G2の完了ゲート

1職種・1業務で、本人が選べる短時間就労、適正な報酬・安全配慮、人間による異議申立て、当日離脱の代替運用が成立すること。

## 5. G3 技術・健康データ — 監視ではなく安全連携を成立させる

### 根本課題

ウェアラブル、見守り、医療データは個別には存在するが、住宅・職場・医療を横断するデータ連携の目的、権限、責任、停止時の安全設計がない。

### 下位課題

- **G3-1 `[定義]` データを使うユースケースを1つに絞る**
  - 例: 就労中の転倒検知、休憩提案、通院遅延の通知など、便益が具体的なものにする。
  - 「健康状態を常に最適化する」という抽象目的から始めない。
  - 完了条件: 入力、処理、出力、誰が行動するか、便益が説明できる。

- **G3-2 `[設計]` データ領域を分離する**
  - 住宅、ウェアラブル、医療、雇用、顧客、モビリティを同じデータベースに集約しない。
  - 雇用へ渡すのは、生データではなく目的限定の職務制約・安全通知にする。
  - 完了条件: データフロー図、目的別アクセス権、保存期間、削除方法がある。

- **G3-3 `[設計]` 共通データモデルとAPIを決める**
  - 観測値、時刻、単位、品質、由来、同意状態を標準化する。
  - 医療・雇用・モビリティのIDを同一番号にせず、期限付きの目的別連携にする。
  - 完了条件: 1ユースケースを複数ベンダーのデータで再現できる。

- **G3-4 `[合意]` 本人のデータ権限を実装する**
  - 同意、目的変更時の再同意、撤回、本人閲覧、代理人設定、二次利用、削除を用意する。
  - 同意できない人がサービスから排除されない代替手段も設ける。
  - 完了条件: 本人が「誰が、何のために、いつまで使うか」を確認できる。

- **G3-5 `[運用]` アラートの責任連鎖を決める**
  - 検知、一次確認、本人への通知、現場対応、医療判断、家族連絡を分ける。
  - 誤警報と見逃しの扱い、夜間・通信断時の代替を決める。
  - 完了条件: アラート発生から人が対応するまでの手順と責任者がある。

- **G3-6 `[運用]` 安全側に倒れる仕組みを作る**
  - 通信断、端末故障、サイバー攻撃、誤判定時に、サービスを安全に縮退させる。
  - 監視を止めても人間の見守り・連絡網で最低限の安全を維持する。
  - 完了条件: 通信・端末・データ基盤の障害演習を実施している。

- **G3-7 `[評価]` 医療的有効性と運用便益を分けて検証する**
  - これは診断・治療なのか、安全支援なのか、研究なのかを分ける。
  - アラート精度、対応時間、本人受容、離脱率、事故、誤警報を記録する。
  - 完了条件: 「健康を改善した」と過大主張せず、測定できた効果だけを報告できる。

### G3の完了ゲート

1ユースケースについて、最小データ・本人同意・責任者・停止時の代替・評価指標が揃い、生体データを雇用選別に使わないことを確認できること。

## 6. G4 技術・アシスト — 機器導入ではなく移動・作業を成立させる

### 根本課題

パワードスーツや移動支援機器を導入するだけでは、高齢者の日常利用にはならない。まず環境、導線、休憩、情報、保守を整え、必要な機器だけを組み合わせる必要がある。

### 下位課題

- **G4-1 `[定義]` 具体的な人・作業・経路を決める**
  - 例: 自宅→診療所、駅→店舗、休憩所→接客場所、バックヤード→売場。
  - 完了条件: 1本のルート上の段差、距離、待ち時間、姿勢、荷物、トイレ、休憩位置が記録される。

- **G4-2 `[設計]` 機器より環境を先に改善する**
  - 段差解消、日陰、ベンチ、手すり、照明、案内、床面、扉、トイレ、荷物導線を整える。
  - 「同じルートを誰でも使える」「移動を減らす」を原則にする。
  - 完了条件: 機器を使わない場合でも、移動の断念率が下がる。

- **G4-3 `[設計]` 機器要件を利用者側から定義する**
  - 重さ、装着時間、操作の学習量、音・光、清掃、充電、故障時、身体差、車いすとの併用を定義する。
  - 完了条件: 仕様書が「最高出力」ではなく、2時間×分散利用の現場条件で書かれている。

- **G4-4 `[運用]` 共有・個別利用・保守を決める**
  - 貸出、予約、サイズ調整、消毒、電池、点検、紛失・破損責任を決める。
  - 完了条件: 利用者が機器を使いたい時に使え、故障時の代替がある。

- **G4-5 `[運用]` 危険を機器で温存しない**
  - 重量物、長時間立位、高温、転倒、衝突を、アシスト機器で無理に継続させない。
  - 作業分割、スタッフ配置、環境改修を先に検討する。
  - 完了条件: 「機器があるから危険作業を続ける」状態になっていない。

- **G4-6 `[合意]` 学習コストを下げる**
  - 初回説明、練習、装着支援、認知・視覚・聴覚への配慮、使わない選択肢を用意する。
  - 完了条件: 利用者本人が、介助者に頼らず安全に開始・停止できる。

- **G4-7 `[評価]` 生活上の便益を測る**
  - 外出断念率、移動完了率、所要時間、疲労、介助者負担、転倒・ヒヤリハット、機器稼働率を測る。
  - 完了条件: 機器導入数ではなく、行きたい場所へ行けた割合が改善している。

### G4の完了ゲート

UADの考え方で、1本の頻出ルートを環境・情報・機器の順に改善し、外出断念率と介助者負担を測定できること。

## 7. G5 医療 — エイジング医療を安全な実証へつなぐ

### 根本課題

研究シーズを「長寿」「若返り」として売り出すだけでは、臨床的価値・安全性・規制適合性が不足する。高齢者と海外患者を対象にするなら、国内医療への影響と本人保護を先に解く必要がある。

### 下位課題

- **G5-1 `[定義]` 医療価値を疾患・機能単位で定義する**
  - 「老化を止める」ではなく、転倒、フレイル、代謝、認知、回復、就労継続など、測定可能な目的にする。
  - 完了条件: 対象者、介入、比較対象、アウトカム、期間が明確である。

- **G5-2 `[設計]` 研究から臨床への移行経路を作る**
  - 基礎研究、前臨床、治験、承認済み医療、自由診療、生活支援を混同しない。
  - 完了条件: 1テーマについて、必要な研究・臨床・規制・資金の段階表がある。

- **G5-3 `[合意]` 高齢者・脆弱な人の保護を設計する**
  - 説明、同意能力、家族・代理人、撤回、費用、期待値、利益相反を扱う。
  - 医療を受けることやデータ提供を、就労・住居・観光の条件にしない。
  - 完了条件: 倫理審査と本人説明の手順が、サービス設計の前提に組み込まれている。

- **G5-4 `[法務]` 医療行為と周辺サービスの境界を確定する**
  - 診断、治療、健康支援、通訳、予約、データ解析、研究参加の責任者を分ける。
  - 完了条件: 各機能の医療責任主体、必要資格、広告表現、記録義務が明確である。

- **G5-5 `[運用]` 国内患者のアクセスを守る**
  - 国際患者を増やすことで、国内の待ち時間、医療費、人材、病床が圧迫されないかを測る。
  - 完了条件: 国際患者受入の上限、優先順位、国内患者への影響監視がある。

- **G5-6 `[設計]` 国際患者の前後工程を作る**
  - 予約、説明、翻訳、査証、支払い、治療、退院、帰国後フォロー、緊急時の連携をつなぐ。
  - 完了条件: 医療機関が単独で背負わず、コーディネーターと責任分担がある。

- **G5-7 `[設計]` 長期コホートと二次利用を分ける**
  - 研究参加、就労データ、医療記録、顧客データの同意と利用目的を分離する。
  - 完了条件: 二次利用を拒否しても、治療・就労・移動の権利が失われない。

- **G5-8 `[評価]` 成功を来訪者数だけで測らない**
  - 臨床アウトカム、安全、説明理解、国内医療への影響、費用、帰国後の継続性を測る。
  - 完了条件: 医療的な便益と観光・売上を別々に報告できる。

### G5の完了ゲート

1テーマについて、医療的に測定可能な仮説、倫理・規制経路、国内医療を守る上限、臨床責任者、長期評価計画が揃うこと。

## 8. G6 文化 — 高齢就労を誇りと選択として成立させる

### 根本課題

「高齢者が働く都市」は、本人の誇りにも、働かせる都市にも見える。技術や観光より先に、誰が何を選び、誰が利益を得て、誰が断れるかを定義しなければ社会的に成立しない。

### 下位課題

- **G6-1 `[定義]` 目指す物語を具体化する**
  - 「高齢者を働かせる」ではなく、「経験を持つ人が、働く・教える・休む・見守る役割を選べる」と定義する。
  - 働かない人、障害のある人、ケアを担う人も同じ価値を持つことを明記する。
  - 完了条件: 当事者が自分の言葉で肯定・拒否できるコンセプト文がある。

- **G6-2 `[合意]` 当事者を共作者にする**
  - 高齢者、障害当事者、家族、若者、労働者、地域住民を企画・評価・広報の段階から入れる。
  - 完了条件: 当事者が意思決定権を持つ会議体と、意見が反映された記録がある。

- **G6-3 `[合意]` 倫理憲章を先に決める**
  - 報酬、勤務時間、撮影、データ、医療、離脱、広告、苦情、事故、AI利用の基準を公開する。
  - 完了条件: 参加前に説明でき、参加後に監査できるルールになっている。

- **G6-4 `[設計]` 「見世物」と「参加型体験」を分ける**
  - 観光客が消費する対象を高齢者本人に置かず、本人が選んだ技能・知識・作品・サービスに置く。
  - 完了条件: 体験の設計書に、本人の役割、報酬、撮影範囲、拒否方法が記載されている。

- **G6-5 `[設計]` 役割の多様性を確保する**
  - 接客だけでなく、設計、教育、調査、品質管理、記録、運営、意思決定などを用意する。
  - 完了条件: 年齢・性別・障害・文化背景の違いで役割が固定されない。

- **G6-6 `[運用]` 物語と利益の権利処理をする**
  - 写真、映像、発言、技能、名前、過去の職歴、アーカイブの二次利用を別々に同意する。
  - 完了条件: 参加者が公開範囲と利用期間を選べ、撤回が将来の不利益にならない。

- **G6-7 `[評価]` 尊厳を測る**
  - 自己決定感、誇り、疲労、安心、地域とのつながり、批判・苦情、継続意向を測る。
  - 完了条件: 来訪者の満足度だけでなく、参加者側の便益が公開される。

### G6の完了ゲート

倫理憲章、当事者の意思決定参加、適正報酬、離脱権、撮影・データ・二次利用の同意が、パイロット開始前に揃うこと。

## 9. G7 記憶 — 失われる前に記録し、次世代へ渡す

### 根本課題

記憶・技能は、後から技術で復元できない。収録対象の選定、本人の権利、記録の質、保存、継承の仕組みを同時に作らなければ、単なる映像倉庫で終わる。

### 下位課題

- **G7-1 `[定義]` 何を優先して残すか決める**
  - 昭和・平成の仕事、生活技術、地域史、商店街、食、道具、言葉、失敗、価値観を候補化する。
  - 年齢だけでなく、希少性、継承可能性、本人の意思、失われる速度で優先順位を付ける。
  - 完了条件: 最初の収録対象リストと選定基準がある。

- **G7-2 `[合意]` 本人の記憶を本人の資産として扱う**
  - 録音・撮影、公開、教育利用、商用利用、AI学習、海外利用、撤回を分けて同意する。
  - 完了条件: 語り手・技能者が、利用先・期間・報酬・クレジットを理解して選べる。

- **G7-3 `[設計]` 収録プロトコルを標準化する**
  - 音声、映像、実演、道具、場所、時代、語彙、背景、本人の解説を一緒に記録する。

  - 人、技能、地域、年代、道具、工程、難易度、言語、権利、公開範囲を付与する。

  - 完了条件: 収録物を「誰が・どこで・何を・どう教えられるか」で検索できる。

- **G7-5 `[運用]` 長期保存と権利管理を分ける**
  - 原本、編集版、公開版、バックアップを分離し、形式、保存先、移行、災害復旧を決める。
  - 完了条件: 運営主体が変わっても、原本と権利情報が失われない。

- **G7-6 `[設計]` アーカイブを継承カリキュラムに変える**
  - 見るだけでなく、弟子入り、ワークショップ、学校・店舗での実演、評価、修了証へつなげる。
  - 完了条件: 1技能について、収録→練習→実演→評価→次の教え手の流れがある。

- **G7-7 `[合意]` 収録者・継承者に報いる**
  - 収録謝金、講師報酬、再利用収益、クレジット、知財の帰属を設計する。
  - 完了条件: 無償提供を前提にせず、価値が発生した時の還元方法が決まる。

- **G7-8 `[評価]` 記録数ではなく継承を測る**
  - 語り手数、技能数、利用可能な記録、継承者数、実演回数、再利用、本人満足を測る。
  - 完了条件: 「何本撮ったか」から「誰が次にできるようになったか」へ評価を移せる。

### G7の完了ゲート

最初の収録対象について、本人同意・権利・標準収録・保存・検索・継承先・報酬が揃い、実際に1技能が次の人へ渡り始めていること。G7は時間切れ型なので、他の制度設計を待たずに着手する。

## 10. G8 資本 — 超長期構想を段階投資へ変える

### 根本課題

75年の完成像に一括投資することはできない。パイロット、地区、複数地区、国際展開を、各段階で独立採算・判断可能な事業に分ける必要がある。

### 下位課題

- **G8-1 `[設計]` 資産と責任を事業体に分ける**
  - IP・ブランド、施設・不動産、雇用・サービス、医療、データ信託を一社に集約しない。
  - 完了条件: どの会社・SPVが、どの資産、費用、事故、データ、収益を持つか決まる。

- **G8-2 `[評価]` 1地区の単位経済性を出す**
  - 参加者数、店舗・施設数、勤務時間、来訪者、客単価、人件費、保険、データ・医療・交通コストを分ける。
  - 完了条件: 小規模パイロットでも赤字要因と黒字化条件が説明できる。

- **G8-3 `[設計]` 収益と公共財を分ける**
  - 体験、サービス利用、施設運営、研究、医療コーディネーション、教育、ライセンスを区別する。
  - アーカイブ、基盤データ、アクセシビリティなど、収益化しにくい公共財の財源を別に置く。
  - 完了条件: 収益事業が公共サービスをただ乗りせず、補助金の目的も明確である。

- **G8-4 `[設計]` 資本の期間とリスクを合わせる**
  - 自治体・補助金、事業会社、デベロッパー、インパクト投資、年金・政府系資金の役割を分ける。
  - 完了条件: パイロット、地区拡張、長期インフラで、資金源と要求リターンが対応している。

- **G8-5 `[設計]` 段階的な出口を作る**
  - 配当、事業売却、REIT化、ライセンス、SPVの継続・分離などを、公共性を壊さない形で設計する。
  - 完了条件: 次の資金を呼ぶ条件と、投資家が撤退してもサービスを継続する方法がある。

- **G8-6 `[運用]` 事故・評判・技術陳腐化に備える**
  - 保険、引当、ベンダー切替、災害、重大事故、データ漏えい、医療訴訟、ブランド毀損を見積もる。
  - 完了条件: 1つの事故で全体が破綻しない責任・資本分離ができている。

- **G8-7 `[合意]` 利益と負担の配分を合意する**
  - 高齢者、住民、自治体、事業者、投資家、医療機関、データ提供者に誰がどの価値を返すかを定める。
  - 完了条件: 参加者の報酬、地域還元、利用料金、補助の受益者が説明できる。

- **G8-8 `[評価]` Go / No-Go条件を先に置く**
  - EBITDAだけでなく、安全、継続率、自己決定、地域受容、データ信頼、医療アクセスを投資ゲートにする。
  - 完了条件: 目標未達時に、縮小・修正・中止する条件が事前合意されている。

### G8の完了ゲート

1地区の収支モデル、資金構成、リスク分担、投資家の出口、公共価値、継続・中止基準が揃い、次の投資が「夢」ではなく条件付き判断になること。

### G9の完了ゲート

## 12. G10 モビリティ・翻訳 — 技術を生活圏の運用に落とす

### 根本課題

自動運転・同時翻訳の技術成熟を待つだけでは、生活者の「行けない」「伝わらない」は解決しない。対象経路、ODD、有人支援、翻訳のリスク分け、災害時の代替を先に設計する必要がある。

### 下位課題

- **G10-1 `[定義]` 1つのODと対象者を決める**
  - 自宅→診療所、駅→店舗、ホテル→医療機関など、利用頻度と失敗時の影響が大きい経路を選ぶ。
  - 車いす、視覚・聴覚・認知、外国語話者、高齢就労者を含めて対象者を決める。
  - 完了条件: 起点、終点、時間帯、需要、既存手段、困っている場面が可視化される。

- **G10-2 `[評価]` 現行交通の断念点を測る**
  - 待ち時間、乗降、段差、乗換、予約、案内、支払い、通訳、天候による断念を記録する。
  - 完了条件: 技術導入前のベースラインと、改善すべき上位3箇所がある。

- **G10-3 `[設計]` 道路・停留所・施設を一体で整える**
  - 乗降場所、歩道、屋根、ベンチ、トイレ、照明、案内、信号、施設入口を設計する。
  - 完了条件: 車両だけを導入せず、乗る前後の経路が連続している。

- **G10-4 `[運用]` 自動運転は限定ODDから始める**
  - 速度、天候、時間帯、路線、遠隔支援、現場スタッフ、手動切替、停止条件を決める。
  - 完了条件: 技術が止まっても、利用者を安全に降ろし、代替手段へつなげられる。

- **G10-5 `[法務]` 事故・保険・責任を決める**
  - 車両、運行、遠隔支援、道路、施設、予約、データ、翻訳の責任境界を決める。
  - 完了条件: 事故時に「技術ベンダーの問題」で終わらない責任連鎖がある。

- **G10-6 `[設計]` 翻訳をリスク階層で分ける**
  - 日常会話、観光案内、仕事の指示、医療、契約、安全説明を同じ自動翻訳に任せない。
  - 医療・契約・事故・同意など高リスク場面は人間確認へ切り替える。
  - 完了条件: 翻訳の誤りが許容されない場面と、確認者・用語集・記録が決まっている。

- **G10-7 `[設計]` 予約・決済・本人支援をつなぐ**
  - 予約、乗降、支払い、行き先変更、付き添い、緊急連絡、翻訳を一つの利用フローにする。
  - 完了条件: アプリを使えない人にも、電話・窓口・現場支援の代替がある。

- **G10-8 `[運用]` 災害・通信断・保守に耐える**
  - 自動運転、翻訳、決済、通信が停止した時の紙・有人・無線・避難誘導を設計する。
  - 完了条件: 平常時の利便性より安全を優先して縮退できる。

- **G10-9 `[評価]` 移動完了と意思疎通を測る**
  - 外出断念率、移動完了率、待ち時間、乗降成功率、事故・ヒヤリハット、翻訳修正率、利用者安心を測る。
  - 完了条件: 利用回数ではなく、目的地へ安全に到達し、必要な意思疎通ができたかを示せる。

### G10の完了ゲート

1経路・1翻訳場面について、現行手段の断念点、環境改修、限定運行、人間フォールバック、アクセシビリティ、災害時代替、KPIが揃うこと。

## 13. 10領域を横断して必ず解く課題

10領域ごとのリストだけでは、同じ課題を別々に解くことになる。以下は全領域に共通する横断課題である。

- **C1 対象者と実証単位**
  - 10領域すべてを東京全体で扱わず、1地区・1施設・1経路・1職務・1ユースケースに固定する。

- **C2 当事者の選択権**
  - 参加、拒否、一時停止、離脱、データ利用、撮影、医療研究、翻訳補助を個別に選べるようにする。

- **C3 ベースラインと比較方法**
  - 導入前の断念率、移動時間、継続率、疲労、事故、収支、満足度を測る。
  - 単なる導入後の感想で、健康改善や社会的効果を断定しない。

- **C4 データ辞書と出典管理**
  - データ項目、定義、単位、更新日、欠損、利用許諾、匿名化、推計値・代理指標を明示する。

- **C5 責任者と運用主体**
  - 企画者、施設、雇用主、医療機関、交通事業者、データ管理者、当事者代表、監査者を置く。

- **C6 苦情・事故・撤回の処理**
  - 技術の成功デモだけでなく、失敗した時に誰が止め、説明し、補償し、再開を判断するかを決める。

- **C7 公共性と事業性の分離**
  - 収益化する部分と、アクセシビリティ・アーカイブ・住民合意など公共財の部分を別の資金・KPIで管理する。

- **C8 継続・縮小・中止の判断**
  - すべてを拡大する前提にせず、安全・本人便益・地域受容・単位経済性の条件で次段階を判断する。

## 14. 依存関係と優先順位

10領域は並列に完成させるものではない。最初の実証に必要な依存関係は次の順になる。

| 段階 | 先に解く課題 | 次に渡すもの |
|---|---|---|
| 0. 時間切れ対応 | G7-1〜G7-4、G6-3 | 記憶・権利・倫理の最低限の基盤 |
| 1. 人が参加できる条件 | G6-2〜G6-7、G2-1〜G2-3 | 本人が選べる1業務と参加条件 |
| 2. 生活圏での実証 | G4-1〜G4-7、G10-1〜G10-3 | 1経路・1施設・1業務の現場設計 |
| 3. 安全な連携 | G3-1〜G3-7、G2-4〜G2-7 | 必要最小限のデータ連携と緊急対応 |
| 4. 事業としての成立 | G8-1〜G8-8、G1-1〜G1-5 | 1地区の収支、制度論点、投資ゲート |
| 5. 外部拡張 | G9-1〜G9-8、G5-1〜G5-8、G1-6〜G1-7 | ブランド、医療、特区、国際展開の拡張判断 |

### 重要な順序

1. **G7は待たない**。記憶・技能の収録は、他領域の技術成熟を待つ理由がない。
2. **G6とG2を先に置く**。本人の選択権と報酬・安全がない状態で、観光・AI・医療を載せない。
3. **G4とG10は1経路に絞る**。都市全体のモビリティ網ではなく、最も頻出する断念経路を解く。
4. **G3は最小限から始める**。全面的な健康監視ではなく、1つの安全ユースケースだけを連携する。
5. **G1とG8は実証の後ろに置く**。特区と長期資本を先に要求せず、制度と投資を動かす証拠を作る。
6. **G5は安全・制度・国内医療影響のゲート後に拡張する**。医療ツーリズムを最初の集客仮説にしない。

## 15. ハッカソンで作るべきものへの反映

この分解を踏まえると、ハッカソンの成果物は10領域を実装するサービスではなく、**次の実証で潰すべき下位課題を、地区・施設・経路・KPIに結び付けて確定する道具**になる。

前回案の **SILVERPUNK PROOF MAP** は維持できるが、単なる「地区ランキング」では不十分である。出力を次のように拡張する。

### PROOF MAPの出力

1. 候補地区の比較
2. 指標、出典、更新日、スコア内訳、重みの表示
3. 1地区の選定
4. 対象施設・対象者・最初の移動経路・最初の業務の仮置き
5. G1/G2/G4/G6/G10の未解決下位課題チェックリスト
6. 最初の実証KPIとベースラインの出典
7. 次の30日で行う調査・合意・現地確認の担当者
8. 継続・縮小・中止の判断条件を含む1ページのパイロットカード

### ハッカソンで扱う範囲

- **扱う**: 地区選定、需要・危機、地域資源、施設・移動の近接性、候補業務、下位課題一覧、KPI設計、出典表示
- **扱わない**: 三層ヘルスモニタリングの本実装、AIによる採用・配置、自動運転車両、医療ツーリズム制度、特区申請、2100年の収益・来訪者・健康寿命の予測
- **原則**: ルールベースで再現可能にし、2100年の人口シナリオは予測ではなくストレステストとして表示する
- **評価**: 2分で問題・利用者・次の判断が伝わる、東京都オープンデータが中心にある、スコアが説明可能、1つの行動へ収束する、当事者を監視対象にしない

### PROOF MAPの完了条件

- 1地区を選べる
- 最大3地区を同じ指標で比較できる
- 1施設・1経路・1業務まで仮説を絞れる
- 未解決課題をG1〜G10のIDで追跡できる
- 各課題に「次に確認する証拠」「担当者」「期限」「中止条件」がある
- 推計値・代理指標・実測値を区別できる
- 操作後に、次の30日間の現地検証へ移れる
