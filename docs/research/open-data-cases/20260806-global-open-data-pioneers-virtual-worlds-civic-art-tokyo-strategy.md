## エグゼクティブサマリー

本調査の結論は、先進的なオープンデータ政策の成否を分けるのは、データセット数ではなく、**「発見できる」「機械で扱える」「法的に再利用できる」「継続更新される」「利用者が改善要求を返せる」「サービス・研究・表現に変換される」「成果を測定する」までを一つの循環として設計できるか**である。英国と米国は全国カタログと標準化を、エストニアは安全な相互運用を、台湾は市民社会との共創を、ニューヨーク市は法定公開・教育・文化イベントを、ロンドン交通局は民間アプリ市場と経済効果測定を、それぞれ強みにしている。これらは同じ「オープンデータ」でも、政策レバーが異なる。

特に重要な示唆は次の通りである。

| 戦略的発見 | 根拠となる事例 | 東京都への意味 |
| :-- | :-- | :-- |
| カタログは終点ではなく、データ供給網の入口である | 米国Data.govは2025年に公開検索をPython／Flask＋OpenSearchへ移行し、CKANを機関向け在庫管理に残した。英国も2026年にdata.gov.ukをNational Data Libraryへ転換中である。 | CKANの維持だけでなく、検索品質、メタデータ収穫、主題別コレクション、AI向け品質保証を分離・高度化する必要がある。 |
| 「全面公開」と「安全な共有」を混同しない | エストニアの中核はX-Roadによる分散型・監査可能なデータ交換であり、全行政データの一般公開ではない。 | 個人・機微データは公開せず、認可付きデータスペースや安全な分析環境で公共価値を生む二層構造が必要である。 |
| 法制度だけでなく、利用者育成と文化化が必要 | NYCは公開義務、データ辞書、更新・保存ルールに加え、Open Data Week、School of Data、Data Through Designを常設化している。2025年のOpen Data Weekは6,200人超、Data Through Designは1,500人超を集めた。 | 東京都はハッカソンを単発イベントから、年間を通じた教育・委託・展示・調達への導線に変えるべきである。 |
| 経済効果は第三者サービスを含めて測る | TfLのオープンデータは600超のアプリを支え、ロンドン市民の42%が利用し、旅客の時間節約だけで年£70–90m相当と推計された。 | データ閲覧数ではなく、外部アプリ利用者、時間短縮、追加需要、事業者売上、行政回避費用を測定する必要がある。 |
| ゲーム・仮想世界は「データを体験可能にする媒体」である | Ordnance Surveyは地形オープンデータから英国全土のMinecraft世界を生成し、初期版は数か月で5万超ダウンロードされた。Block by BlockはMinecraftを住民参加型の都市設計言語にした。 | 防災、再開発、公園、交通、子育て施設配置を、3D都市モデルとゲームエンジンで検討する「公共シミュレーション層」が有効である。 |
| アートは利用促進ではなく、解釈・異議申立て・記憶の装置になる | ODIのData as Culture、NYCのData Through Design、Theaster Gatesのアーカイブ型社会彫刻は、データや記録を専門家以外が議論できる公共文化へ変換する。 | 文化事業を「可視化の装飾」にせず、データの欠落、偏り、歴史的不可視化を検証する公共的レビュー機能として位置付けるべきである。 |

東京都は2026年8月時点でCKANベースのカタログに9,647件のデータセットを掲載し、API、活用事例、可視化事例、全文検索、ハッカソン、東京データプラットフォーム、デジタルツインをすでに持つ。したがって次の競争軸は「公開量の増加」よりも、**高価値データのサービス水準保証、民間・研究・市民による再利用の追跡、機微データの安全な共有、3D・ゲーム・アートへの変換、成果連動型の資金配分**である。

## 調査設計と評価枠組み

本報告では「オープンデータ」を、単にウェブで閲覧できる情報ではなく、原則として機械可読で、明確な再利用条件があり、技術的・法的・経済的障壁が低いデータと捉えた。ただし、指定範囲には、エストニアの行政データ交換、Second Lifeのオープンソース・ビューア、Minecraftを使う参加型設計、Theaster Gatesの社会彫刻のように、厳密なオープンデータとは異なる事例も含まれる。このため、以下の三類型を区別した。

| 類型 | 判定基準 | 代表例 |
| :-- | :-- | :-- |
| 厳密なオープンデータ | 機械可読、再利用可能なライセンス、継続的提供、APIまたは一括取得 | Data.gov、NYC Open Data、HRI、TfL、Safecast |
| 共有データ／デジタル・コモンズ | 一般公開ではないが、標準化された安全な交換、市民共同管理、オープンソース基盤を持つ | X-Road、DECODE、Ushahidi、OpenStreetMap |
| オープンデータ隣接型の公共表現 | データ・記録・モデルを参加、批評、記憶、空間形成へ変換するが、元データの全面公開や標準ライセンスは限定的 | Block by Block、Second Life、Data as Culture、Theaster Gates |

評価軸は、公開範囲、データ品質、更新性、相互運用性、ライセンス明確性、プライバシー保護、利用者参加、民間・市民エコシステム、財源の持続性、定量的成果、東京都への移植可能性とした。成果は、データセット件数のような供給指標、アプリ数・利用者数のような利用指標、時間節約・投票率・公共空間整備のようなアウトカムを分けて扱う。供給量だけを成功とみなさない。

また、各事例の数字は同じ母集団・期間・測定方法ではない。たとえば米国の「363,781データセット」はカタログ規模、Safecastの「1億5千万件超」は観測レコード、NYCの「6,200人超」はイベント参加者であり、横並びの優劣には使えない。各数値は、その事例がどの段階の成果を測っているかを示す証拠として読むべきである。

## 政府・自治体・民間エコシステムの事例

**国レベルの先駆事例要約**

| 事例 | 概要・目的・公開データ | 技術スタック／プラットフォーム | ガバナンス・ライセンス | 資金・持続性 | 成果 | 課題・教訓 | 東京都への適用可能性 |
| :-- | :-- | :-- | :-- | :-- | :-- | :-- | :-- |
| 英国 data.gov.uk／National Data Library | 2010年開始の公共データ検索基盤を、2026年から高品質な主題別コレクション、データ・マニュアル、既存ディレクトリを統合するNational Data Libraryへ転換。統計、交通、環境、住宅、公共サービス等を扱う。 | 既存ディレクトリはCKAN 2.7、CKAN APIと拡張を利用。APIキー不要・公表上はレート制限なし。主題別コレクションは調査時点でAPI未対応。 | ポータル内容は原則Open Government Licence v3.0。個別データは別ライセンスの場合がある。GDS／National Data Libraryチームが運営。 | NDLは歳出見直し期間に£100m超の政府投資で支援。既存ポータル単体の年次運営費は不明。 | 全国共通ライセンスと長期運営を制度化。2026年は「量中心のディレクトリ」から「信頼できる高価値コレクション」へ移行中で、最終成果は未確定。 | 古いメタデータ、リンク切れ、品質差を抱える大規模カタログは、検索改善だけでは解決しない。主題別キュレーション、責任者、品質指標、AI利用適合性が必要。 | 「東京版データライブラリ」として、防災、移動、子育て、脱炭素などのミッション別コレクションを設け、カタログ全件と高品質保証済みデータを区別する。 |
| 米国 Data.gov | 2009年開始。連邦政府のデータ、ツール、研究・アプリ開発資源を横断検索する。2013年の大統領令とOpen Data Policyで、原則として機械可読・オープンを情報ライフサイクルに組み込んだ。 | 2025年に公開検索catalog.data.govをCKANからPython／Flask＋OpenSearchへ移行。harvest.data.govが自動メタデータ収穫、inventory.data.govはCKANを継続。DCAT-US／data.jsonを利用する。 | GSA、OMB等が政策・基盤を担い、各機関が自らのメタデータ品質に責任を持つ。連邦政府データは公有領域が多いが、個別データのライセンス欄を管理する。プライバシー・機密・安全保障の事前評価を要求。 | 連邦予算による継続運営。Data.gov単体の最新年次総費用は不明。オープンソースのコードと標準を再利用することで機関横断コストを抑える。 | 2026年8月6日時点で363,781データセット。大規模分散型カタログと自動収穫を確立。 | 収穫元の誤記や欠損を中央が自動修正しないため、規模拡大と品質低下が同時に起こりうる。検索基盤と発行機関の品質責任を分離した点が教訓。 | 都・区市町村・外郭団体のメタデータを自動収穫し、発行者別SLA、エラー率、更新遅延を可視化する。検索と内部在庫管理を別コンポーネント化する。 |
| エストニア e-Estonia／X-Road／Open Data Portal | 行政サービスをオンライン化し、分散した官民データベースを安全に接続する。公開データポータルも持つが、中核は「データを一か所に集めない」相互運用基盤である。 | X-Roadによる分散型データ交換、電子ID、ログ・認証・暗号化。公開データポータルは2021年初頭に約800データセット、100超の発行者。 | 行政機関が原本データを保持し、認可された照会を交換する。2017年には国外にバックアップするデータ大使館を世界で初めて開設。公開データの個別ライセンスはデータごとに確認が必要で、統一状況は本調査では不明。 | 国家デジタル基盤として公的資金で継続。X-Road・公開データ単体の最新総費用は不明。 | 公共サービスの100%がオンライン利用可能とされ、年間1,400人年相当を節約。税申告の99%がオンラインで、所要時間約3分。企業の99%がオンライン設立可能。 | 成功を「公開件数」で説明すると本質を誤る。本人同意、アクセス権、監査ログ、データ最小化を伴う安全な共有が、全面公開より重要な領域がある。 | 東京都はオープンカタログの外側に、医療、福祉、モビリティ、防災の認可付きデータ交換層を設ける。都民が「誰が自分のデータを参照したか」を確認できる監査機能が重要。 |
| 台湾 Open Data／g0v／vTaiwan | 政府データ公開と、市民技術コミュニティg0v、参加型政策形成vTaiwanを結び付けた共創モデル。2014年前後からオープンデータ、ビッグデータ、クラウドソーシングを国家的方向として推進した。 | 政府オープンデータ・ポータル、API、機械可読データ、g0vのオープンソース開発、vTaiwanのオンライン熟議ツール群。個別データは継続更新される。 | 政府資料開放授權條款（Open Government Data License）v1.0が再利用条件を標準化。g0vやvTaiwanは政府組織の下請けではなく、市民社会側の自律性を保つ。 | 政府ポータルは公費。vTaiwanやCofacts等の市民側は非営利・寄付を含む複線的資金。個別年度額は不明。 | 公開データを政策参加、ファクトチェック、市民開発へ接続したことが成果。統一された最新の定量評価は不明。 | 参加を行政主催イベントに閉じると、批判性と自律性が弱まる。政府はAPI、担当者、応答期限を提供し、市民側の独立した課題設定を認める必要がある。 | 東京都版g0v型コミュニティに、データ改善提案権、少額助成、庁内担当者への定例アクセスを与える。都が成果物を囲い込まないことが条件。 |

英国と米国は、いずれも全国カタログの先駆者だが、2025〜2026年の動きは「CKANを置けば十分」という初期モデルからの離脱を示す。英国は高品質な主題別コレクションとデータ・マニュアルへ、米国は公開検索、収穫、機関内在庫を別サービスへ分解した。東京都も、カタログ・検索・発行ワークフロー・品質監視・安全な共有・AI向け提供を一枚岩のシステムにせず、交換可能な部品として運営する方が持続性は高い。

エストニアから得るべき最大の教訓は、オープンデータ政策を「何でも公開する政策」にしないことである。公開可能な統計・地理・予算・施設データはオープン化し、個人単位の医療・福祉・税・教育データは、X-Road型の認可・ログ付き交換、あるいは安全な分析環境で扱う。公開と共有を制度的に分ければ、プライバシー保護を理由にデータ活用全体が止まることを避けられる。

台湾モデルの核心は、政府が市民参加を「意見募集」に限定せず、市民側がコード、可視化、論点設定、検証基盤を自律的に作れる余白を維持したことにある。東京都への移植では、行政がテーマ、審査、成果物の所有権をすべて決める通常の委託方式より、公開課題、マイクログラント、オープンソース、データ担当者との協働、採用時の公正な調達を組み合わせる方が近い。

TfLは、民間連携の最も実務的な先例である。行政が最終アプリをすべて作るのではなく、信頼できるリアルタイムデータ、仕様、変更管理を提供し、民間が利用者体験を競う。公的価値は、外部アプリ数、利用率、時間節約、追加旅行、付加価値として評価される。東京都では、都営交通だけを対象にすると便益が限定されるため、民間鉄道、バス、タクシー、シェアモビリティ、道路、歩行者空間を、官民共通のデータ契約と可用性SLAで束ねることが重要になる。

BarcelonaとOpenStreetMapは、データの公共性をライセンスだけでなく、共同管理の仕組みとして捉える。BarcelonaのDECODEは個人・共同体の利用条件を、OpenStreetMapは継承共有とコミュニティ合意を重視する。東京都が民間データを取り込む際も、単なる購入ではなく、目的、期間、再共有、住民への還元、終了後の扱い、コミュニティへの貢献を契約に組み込むべきである。

SafecastとUshahidiは、市民生成データが行政データの不足を補う一方、品質と安全性の問題を行政側へ持ち込むことを示す。必要なのは、市民データを「非公式だから無視する」か「大量だから信用する」かの二択ではなく、校正済み／未校正、検証済み／未検証、速報／確定、公開可能／保護対象をメタデータで区別し、行政の公式測定や処理履歴と接続することである。

Data as CultureとData Through Designは、アートをオープンデータ政策の末端広報ではなく、データの意味、欠落、権力、分類、感情的影響を検討する公共的インターフェースにした。東京都で同様の制度を作る場合、作品の美観や来場者数だけでなく、作品が発見したデータ欠損、誤分類、表現上の問題、政策仮説を、担当局が正式に回答する仕組みが必要である。

Theaster Gatesの事例は、オープンデータとしては弱いが、「社会彫刻」の観点では重要である。データやアーカイブの価値は、サーバー上で公開されるだけでなく、場所、管理者、解釈共同体、教育、住宅、仕事、保存費用と結び付いて持続する。東京都の文化・地域データ戦略も、デジタル化件数だけでなく、誰が記録を管理し、誰がアクセスでき、地域にどの収益と能力が残るかを設計対象にする必要がある。

**エコシステムの関係図**

成功事例では、行政から利用者への一方向公開ではなく、外部利用、フィードバック、公共調達、品質改善、再投資が循環している。エストニア型の認可共有と、NYC・TfL型の公開データは別レーンだが、共通のガバナンスで接続できる。

> 原文にはフロー図が含まれていた（エクスポートでノードのみが残ったため、以下の構造で置き換える）。

- **行政・公共機関（原データと法的責任）** → 公開可否・リスク分類
  - 公開可能 → **オープンデータ層**（API・一括DL・メタデータ・ライセンス）
    - → 企業・研究者・市民開発者 → アプリ・研究・事業・可視化
    - → ゲーム・3D・アート・教育 → 参加・理解・批評・共同設計
  - 個人・機微 → **安全な共有層**（認可・監査ログ・匿名化・安全分析環境）
    - → 認定研究・行政連携サービス → 個別化支援・政策評価
- 上記の各出口 → **公共アウトカム**（利用指標・時間節約・経済効果）
- 利用側から行政へ戻る経路 → 提案・異議・欠測発見 → **データ改善チケット**
- 公共アウトカム → **予算・調達・SLAの更新**

**先駆事例に共通する好循環**

好循環は、概ね次の順序で生まれる。

1. 法令、規程、ライセンスにより「公開・更新・説明責任」を平常業務にする。
2. API、標準語彙、識別子、データ辞書、変更履歴により再利用コストを下げる。
3. 開発者、研究者、市民、アーティスト、地域組織に、小額資金・教育・場所・担当者アクセスを提供する。
4. 外部サービス、研究、作品、住民提案を、行政の調達・政策評価・データ改善へ戻す。
5. データ閲覧数ではなく、時間節約、利用者数、修繕、参加の多様性、事業創出、政策改善を測る。
6. 測定結果を次年度予算、SLA、優先データ、廃止判断へ反映する。

逆に失敗しやすいのは、PDFや表計算ファイルを大量掲載して終了する、ハッカソンを単発開催する、民間サービスに依存しながらAPIの可用性を保証しない、市民生成データを品質区分なしに混ぜる、個人データを「オープン」の名で過剰公開する、アートを無批判な広報にする、といった場合である。

## 東京都への具体的施策

**現状認識**

東京都は、2026年8月6日時点でオープンデータカタログ、CKAN API、9,647件のデータセット、16カテゴリ、活用・可視化事例、全文検索、ラウンドテーブル、ハッカソンを持つ。また、東京データプラットフォームとデジタルツインを並行して進めている。これは「基盤がない」状態ではなく、複数の基盤とイベントを一つの成果循環へ統合する段階である。

現状の公開件数は十分大きいが、件数は更新・統廃合で変動する。したがって目標値を「データセットを何件増やすか」だけに置くと、細分化による見かけの増加、重複、古い月次ファイルの累積を誘発する。東京都は、利用された高価値データの比率、更新遵守率、API可用性、データ辞書完全率、外部サービス利用者、住民便益へKPIを移すべきである。

東京都が目指すべき最終像は、「巨大なデータ置き場」ではなく、次の四層が連動する都市データ・コモンズである。

1. **公開層:** 誰でも再利用できる高品質データ、API、標準識別子、オープンライセンス。
2. **信頼共有層:** 個人・機微データを認可、監査、匿名化、安全環境で利用する仕組み。
3. **創造・参加層:** Civic Tech、研究、企業、ゲーム、3D、教育、アート、地域アーカイブ。
4. **説明責任層:** 利用、便益、偏り、欠測、事故、改善、予算を公開する監査と評価。

この四層が揃えば、オープンデータは広報・透明性施策にとどまらず、交通、防災、福祉、環境、都市計画、文化、産業政策を横断する基盤となる。
